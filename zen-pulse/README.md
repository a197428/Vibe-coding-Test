# ZenPulse — AI Meditation App

Прототип мобильного приложения для медитаций с подпиской и ИИ-аффирмациями.
Стек: React Native + Expo, NativeWind, React Navigation, Zustand.

---

## Контрольный вопрос

**С какими специфическими проблемами мобильной верстки ИИ справляется хуже всего и как контролировать его работу, чтобы приложение не сломалось на маленьких экранах (iPhone SE vs Pro Max)?**

### Где ИИ справляется хуже всего

**1. Скролл и overflow в веб-режиме**
Самая болезненная проблема в этом проекте. ИИ генерирует корректный код для нативного устройства, но не учитывает, что React Navigation Stack в браузере рендерит экраны в `position: absolute` контейнер с `overflow: hidden`. В результате `ScrollView` не скроллится. ИИ не "видит" браузерный DOM и не может самостоятельно диагностировать это — нужна ручная проверка в DevTools.

**2. Фиксированные размеры вместо адаптивных**
ИИ склонен писать конкретные значения в пикселях (`fontSize: 24`, `padding: 20`) вместо адаптивных решений через `Dimensions.get('window')` или процентные значения. На iPhone SE (320pt ширина) крупный текст или широкие карточки могут выходить за границы экрана, тогда как на Pro Max (430pt) тот же интерфейс выглядит разреженным.

**3. Safe Area на разных устройствах**
ИИ часто использует `SafeAreaView` формально, не проверяя реальные отступы. На iPhone SE с iOS 15+ нижняя панель навигации «съедает» контент, если не использовать `useSafeAreaInsets()` с явными `paddingBottom`. На Pro Max с Dynamic Island верхний отступ другой.

**4. Многострочный текст на узких экранах**
Длинные строки в кнопках и заголовках ИИ не тестирует на узких экранах. Текст типа «Разблокируйте все медитации — Улучшить →» на SE может переноситься или обрезаться.

**5. Конфликты версий зависимостей**
ИИ не знает актуальные совместимые версии пакетов на момент генерации. В этом проекте возникли конфликты между Expo SDK 55 и Expo Go 54, между `react-native-worklets` и NativeWind v4 — всё это потребовало ручного вмешательства.

### Как контролировать работу ИИ

**Проверяй на реальных размерах экранов:**
- Всегда тестируй в Chrome DevTools с эмуляцией iPhone SE (375×667) и iPhone 14 Pro Max (430×932)
- Проверяй горизонтальный overflow: в DevTools → Elements → ищи элементы шире viewport

**Явно указывай ограничения в промптах:**
- Говори ИИ: «используй только адаптивные размеры, никаких фиксированных px для ширины»
- Указывай: «проверь что текст не обрезается на ширине 320pt»

**Проверяй скролл вручную:**
- После каждого экрана открывай в браузере и прокручивай до конца
- ИИ не запускает приложение — он не знает, работает ли скролл

**Контролируй зависимости:**
- После `npm install` всегда запускай `npx expo install --fix`
- Не доверяй ИИ выбор версий пакетов — проверяй совместимость в официальной документации Expo

**Code review перед коммитом:**
- Ищи `width: число` и `height: число` — спрашивай ИИ, почему не `'100%'` или `Dimensions`
- Проверяй что все `TouchableOpacity` имеют достаточный `minHeight: 44` (стандарт Apple для touch target)
