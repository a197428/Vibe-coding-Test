# Документ требований

## Введение

ZenPulse — это прототип мобильного приложения на React Native (Expo) для медитаций с голосовым сопровождением. Приложение включает экран подписки (пейволл), библиотеку медитаций с логикой заблокированного/разблокированного доступа, а также функцию ежедневных аффирмаций на основе настроения с использованием ИИ. Прототип симулирует реальный процесс покупки и использует LLM (или реалистичный мок) для генерации персонализированных аффирмаций на основе выбранного пользователем настроения. Весь пользовательский интерфейс приложения отображается на русском языке.

## Глоссарий

- **Приложение**: Мобильное приложение ZenPulse на React Native (Expo).
- **Пользователь**: Человек, использующий Приложение на мобильном устройстве.
- **Подписка**: Симулированная внутренняя покупка, предоставляющая Пользователю доступ к премиум-контенту. Бывает Ежемесячной или Годовой.
- **Экран_Пейволла**: Экран подписки, отображаемый Пользователям, у которых ещё нет активной Подписки.
- **Экран_Медитаций**: Главный экран, отображающий список доступных сессий медитации.
- **Карточка_Сессии**: UI-компонент в виде карточки, отображающий название сессии медитации, обложку и продолжительность.
- **Заблокированная_Сессия**: Сессия медитации, недоступная без активной Подписки.
- **Разблокированная_Сессия**: Сессия медитации, доступная всем Пользователям независимо от статуса Подписки.
- **Выбор_Настроения**: UI-компонент, предлагающий три варианта эмодзи, представляющих разные настроения.
- **Генератор_Аффирмаций**: Сервис, отвечающий за создание короткого текста аффирмации или медитации на основе выбранного настроения.
- **LLM**: Большая языковая модель, используемая Генератором_Аффирмаций для создания текста на основе настроения.
- **Мок_Ответ**: Реалистичный, заранее написанный текст аффирмации, возвращаемый при недоступности живого LLM.
- **Навигатор**: Контроллер навигации, управляющий переходами между экранами.

## Требования

### Требование 1: Экран подписки (пейволл)

**Пользовательская история:** Как Пользователь, я хочу видеть экран премиум-подписки, чтобы понять преимущества и выбрать тариф перед получением доступа к заблокированному контенту.

#### Критерии приёмки

1. КОГДА у Пользователя нет активной Подписки и он переходит к Заблокированной_Сессии, Навигатор ДОЛЖЕН перенаправить Пользователя на Экран_Пейволла.
2. Экран_Пейволла ДОЛЖЕН отображать список не менее четырёх премиум-преимуществ с чётким и лаконичным текстом на русском языке.
3. Экран_Пейволла ДОЛЖЕН предлагать два варианта Подписки: «Ежемесячная» и «Годовая».
4. Экран_Пейволла ДОЛЖЕН визуально выделять вариант «Годовая» как наиболее выгодный тариф с помощью значка или подсветки.
5. Экран_Пейволла ДОЛЖЕН отображать цену для каждого варианта Подписки.
6. Экран_Пейволла ДОЛЖЕН содержать кнопку «Попробовать бесплатно».
7. КОГДА Пользователь нажимает кнопку «Попробовать бесплатно», Приложение ДОЛЖНО симулировать успешную покупку и установить статус Подписки как активный.
8. КОГДА статус Подписки устанавливается как активный, Навигатор ДОЛЖЕН перенаправить Пользователя на Экран_Медитаций.
9. Экран_Пейволла ДОЛЖЕН использовать яркий, премиальный визуальный дизайн, соответствующий эстетике приложений для медитации.

---

### Требование 2: Экран медитаций

**Пользовательская история:** Как Пользователь, я хочу просматривать доступные сессии медитации, чтобы выбрать и начать сессию, подходящую моим потребностям.

#### Критерии приёмки

1. Экран_Медитаций ДОЛЖЕН отображать прокручиваемый список Карточек_Сессий.
2. Приложение ДОЛЖНО включать не менее шести Карточек_Сессий, из которых не менее трёх являются Заблокированными_Сессиями.
3. КАЖДАЯ Карточка_Сессии ДОЛЖНА отображать название сессии на русском языке, обложку и продолжительность сессии в минутах.
4. ПОКА у Пользователя нет активной Подписки, Экран_Медитаций ДОЛЖЕН отображать карточки Заблокированных_Сессий в визуально затемнённом стиле с иконкой замка поверх.
5. ПОКА у Пользователя есть активная Подписка, Экран_Медитаций ДОЛЖЕН отображать все Карточки_Сессий без затемнения и иконки замка.
6. КОГДА Пользователь без активной Подписки нажимает на карточку Заблокированной_Сессии, Навигатор ДОЛЖЕН перенаправить Пользователя на Экран_Пейволла.
7. КОГДА Пользователь нажимает на карточку Разблокированной_Сессии, Приложение ДОЛЖНО отобразить детальный экран сессии или экран-заглушку с деталями.

---

### Требование 3: Функция ежедневных аффирмаций на основе настроения (ИИ)

**Пользовательская история:** Как Пользователь, я хочу выбрать своё текущее настроение и получить персонализированную аффирмацию, чтобы начать медитацию с релевантным и вдохновляющим сообщением.

#### Критерии приёмки

1. Экран_Медитаций ДОЛЖЕН включать секцию «Аффирмация дня (ИИ)», содержащую Выбор_Настроения и кнопку генерации.
2. Выбор_Настроения ДОЛЖЕН предлагать ровно три варианта эмодзи, представляющих разные настроения (например, 😌 спокойствие, 😔 грусть, 😤 стресс), с подписями на русском языке.
3. КОГДА Пользователь нажимает на эмодзи в Выборе_Настроения, Приложение ДОЛЖНО отметить этот эмодзи как выбранный и снять выделение с ранее выбранного эмодзи.
4. КОГДА Пользователь нажимает кнопку генерации с выбранным настроением, Генератор_Аффирмаций ДОЛЖЕН отправить запрос к LLM с просьбой создать короткий текст аффирмации или медитации, адаптированный к выбранному настроению, на русском языке.
5. ПОКА Генератор_Аффирмаций ожидает ответа, Приложение ДОЛЖНО отображать индикатор загрузки вместо текста аффирмации.
6. КОГДА Генератор_Аффирмаций получает ответ, Приложение ДОЛЖНО отобразить текст аффирмации Пользователю.
7. ЕСЛИ LLM недоступен или возвращает ошибку, Генератор_Аффирмаций ДОЛЖЕН вернуть Мок_Ответ, соответствующий выбранному настроению, на русском языке.
8. ЕСЛИ Пользователь нажимает кнопку генерации без выбранного настроения, Приложение ДОЛЖНО отобразить встроенную подсказку с просьбой сначала выбрать настроение.
9. Генератор_Аффирмаций ДОЛЖЕН создавать текст аффирмации объёмом не более 100 слов в одном ответе.

---

### Требование 4: Сохранение статуса подписки

**Пользовательская история:** Как Пользователь, я хочу, чтобы мой статус подписки сохранялся в течение сессии приложения, чтобы не приходилось повторно совершать покупку при каждом переходе между экранами.

#### Критерии приёмки

1. Приложение ДОЛЖНО хранить статус Подписки в глобальном хранилище состояния, доступном всем экранам.
2. ПОКА сессия Приложения активна, Приложение ДОЛЖНО сохранять статус Подписки при навигации между экранами.
3. КОГДА Приложение перезапускается, Приложение ДОЛЖНО сбрасывать статус Подписки до неактивного (поведение прототипа — постоянное хранилище не требуется).

---

### Требование 5: Структура навигации

**Пользовательская история:** Как Пользователь, я хочу плавной и предсказуемой навигации между экранами, чтобы приложение было интуитивно понятным в использовании.

#### Критерии приёмки

1. Навигатор ДОЛЖЕН обеспечивать стековую или вкладочную структуру навигации, связывающую Экран_Пейволла и Экран_Медитаций.
2. КОГДА Пользователь находится на Экране_Медитаций и не имеет активной Подписки, Приложение ДОЛЖНО предоставлять видимую точку входа на Экран_Пейволла (например, кнопку «Улучшить» или баннер).
3. КОГДА Пользователь находится на Экране_Пейволла и уже имеет активную Подписку, Навигатор ДОЛЖЕН перенаправить Пользователя на Экран_Медитаций без отображения Экрана_Пейволла.
